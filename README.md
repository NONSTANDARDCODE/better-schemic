## Your schema lives in four places. None of them agree.

| | |
| --- | --- |
| 🛡️ **Validation** | `email: z.string().email()` — rewritten in every layer, enforced by none of them |
| 🔌 **Queries** | `"SELECT * FROM user WHERE email = " + email` — stringly-typed, no autocomplete |
| 📐 **Types** | `interface User { email: string }` — right until sprint three |
| 🗃️ **DDL + migrations** | `DEFINE FIELD …` and `ALTER TABLE …` — hand-written, by 2am, into a console |

But you already describe your data in TypeScript.

## The whole chain

Nine lines in. Everything out. **Nothing below is hand-written or maintained twice.**

```ts
// database/schema/tables/user.ts
import { defineTable, s, surql } from "better-schemic";

export const User = defineTable("user", {
  name: s.string().$min(1).$max(80),
  email: s.email(),
  role: s.string().$default("member"),
  tags: s.array(s.string()),
  createdAt: s.datetime().$default(surql`time::now()`).$readonly(),
})
  .index("user_email", ["email"], { unique: true })
  .schemafull();
```

**→ the database**

```surql
DEFINE TABLE user TYPE NORMAL SCHEMAFULL;
DEFINE FIELD name ON TABLE user TYPE string ASSERT string::len($value) >= 1 AND string::len($value) <= 80;
DEFINE FIELD email ON TABLE user TYPE string ASSERT string::is_email($value);
DEFINE FIELD role ON TABLE user TYPE string DEFAULT "member";
DEFINE FIELD tags ON TABLE user TYPE array<string>;
DEFINE FIELD createdAt ON TABLE user TYPE datetime DEFAULT time::now() READONLY;
DEFINE INDEX user_email ON TABLE user FIELDS email UNIQUE;
```

`$min`/`$max` are not app-side sugar — they bake into a server-side `ASSERT` that every write, from
every client, obeys.

**→ your types**

```ts
import type { App, Create, Update } from "better-schemic";

type Row = App<typeof User>;      // { id: RecordId<"user">; name: string; email: string;
                                   //   role: string; tags: string[]; createdAt: Date }  ← Date, not a string
type NewUser = Create<typeof User>;   // $readonly excluded · $default fields optional · rest required
type UserPatch = Update<typeof User>;  // createdAt is READONLY, id is immutable
```

Not a cast — `App<>` is the codec's own output type. Refactor the schema and the whole app follows.
No codegen, nothing to remember.

**→ validation, anywhere**

`s.*` **is** a Zod schema. The API you already know works at the edge, in tests, in seeds:

```ts
User.fields.email.safeParse("aeon@nonstandard.dev");   // { success: true,  data: "aeon@nonstandard.dev" }
User.fields.email.safeParse("not-an-email");           // { success: false, error: ZodError }
```

**→ a reviewable, reversible migration**

```bash
sc gen add_users
```

```surql
-- 20261013043706_add_users
-- Generated by better-schemic. Review before applying.

IF $direction = "up" {
    DEFINE TABLE OVERWRITE user TYPE NORMAL SCHEMAFULL;
    DEFINE FIELD OVERWRITE email ON TABLE user TYPE string ASSERT string::is_email($value);
    DEFINE INDEX OVERWRITE user_email ON TABLE user FIELDS email UNIQUE;
    …
} ELSE {
    REMOVE INDEX IF EXISTS user_email ON TABLE user;
    REMOVE TABLE IF EXISTS user;
};
```

Someone hand-writes a `DEFINE` at 2am? `sc pull` walks the live database back into TypeScript. The
source of truth can always be restored.

**→ your queries**

```ts
import { betterSchemic, defineSchema } from "better-schemic/orm";

const client = betterSchemic(db, { schema: defineSchema({ users: User }) });

await client.users.update({ where: { email: "aeon@nonstandard.dev" }, data: { tags: ["db"] } });
```

```surql
UPDATE user MERGE $p1 WHERE email = $p0;
```

That `where` resolved through the `user_email` index declared three sections above. One round-trip,
parameterized, typed. This is the part upstream never finished.

## Typed queries

One delegate per table, typed from the schema, compiling to **one statement** — no N+1, no string
concatenation, no drift.

Typed query layers usually stop at Postgres. Here the TypeScript file **is** the server schema — that
`DEFINE FIELD` came out of the same nine lines this delegate came out of, not out of a translation
layer.

```ts
await client.users.create({ data: { name: "Aeon", email: "aeon@nonstandard.dev", tags: ["graph"] } });
// CREATE type::record(s"user", rand::ulid()) CONTENT $p0;

await client.users.findMany({
  where: { role: "member" },
  select: { id: true, name: true },
  orderBy: [{ createdAt: "desc" }],
  limit: 20,
});
// SELECT id, name FROM user WHERE role = $p0 ORDER BY createdAt DESC LIMIT $p1;

await client.users.upsert({ where: { email }, data: { tags: ["db"] }, onMissing: "create" });
// UPSERT ((SELECT VALUE id FROM user WHERE email = $p0 LIMIT 1)[0] ?? …) MERGE $p1;

await client.users.live({ where: { role: "member" }, diff: true }, onChange);
// LIVE SELECT DIFF FROM user WHERE role = $p0;
```

`select` projects the result type. `where` only accepts real columns and real operators. A typo is a
red squiggle, not a 500. And a bad payload never reaches the wire — the codec rejects it first:

```ts
await client.users.create({ data: { name: "Aeon", email: "nope", tags: [] } });
// BetterSchemicError: Validation failed at "email"  (code: "ValidationError")
```

Reads, writes, `upsert`/`upsertDelta`, relations, transactions with `afterCommit`, live queries,
changefeeds, multi-tenant scoping, plugins — [all mapped, with goldens](packages/better-schemic/docs/ORM-COVERAGE.md).

> The ORM resolves unique targets from **table-level** `.index(…, { unique: true })` — the inline
> `s.email().$unique()` emits the same DDL index but isn't a write target.

## Because it's SurrealDB

Everything below is the same authoring API. No extra config, no plugin, no escape hatch.

**The graph is a type, not a traversal.**

```ts
const Post = defineTable("post", {
  title: s.string(),
  author: s.recordId(User).$reference({ onDelete: "cascade" }),
});
const Likes = defineRelation("likes", { score: s.int().$min(0).$max(5) }).from(User).to(Post);

await client.likes.relate({ from: "user:1", to: "post:1", data: { score: 5 } });
// RELATE user:1->likes->post:1 SET score = $p0;

await client.users.findMany({
  include: { likes: { where: { score: { gte: 4 } }, select: { title: true } } },
  where: { likes: { some: { score: { gte: 4 } } } },
});
// ONE round-trip — edges fetched AND filtered in the same statement
```

**Vector search and full text, declared next to the field.**

```ts
defineAnalyzer("english").tokenizers("blank").filters("lowercase", "snowball(english)");

defineTable("doc", { content: s.string(), embedding: s.array(s.float()) })
  .index("ft", ["content"], { fulltext: { analyzer: "english", highlights: true } })
  .index("vec", ["embedding"], { hnsw: { dimension: 1536, dist: "cosine" } });
```

```surql
DEFINE ANALYZER english TOKENIZERS BLANK FILTERS LOWERCASE, SNOWBALL(ENGLISH);
DEFINE INDEX ft ON TABLE doc FIELDS content FULLTEXT ANALYZER english HIGHLIGHTS;
DEFINE INDEX vec ON TABLE doc FIELDS embedding HNSW DIMENSION 1536 DIST COSINE;
```

**Permissions and views are schema — not a README you forget.**

```ts
defineTable("doc", { id: s.string() }).permissions({
  select: surql`true`,
  create: surql`$auth.id != NONE`,
  update: surql`$auth.id = id.owner`,
});

defineView("adults", { name: s.string(), age: s.number() })
  .as(surql`SELECT name, age FROM user WHERE age >= 18`);
// DEFINE TABLE adults TYPE ANY SCHEMALESS AS SELECT name, age FROM user WHERE age >= 18;
```

**Guardrails ship as plugins, not tribal knowledge.**

```ts
betterSchemic(db, {
  schema,
  plugins: [
    recommended({ maxLimit: 100 }),                 // no raw-unsafe, no unfiltered writes
    timestamps(), softDelete(),                     // audited, reversible soft delete
    tenantRls({ tenant: () => ctx.tenantId }),      // fail-closed multi-tenant scope
  ],
});

await client.customers.findMany({});                          // ✗ TenantRequired
await client.customers.$forTenant("user:abc").findMany({});  // ✓ scoped
```

**A query log you'd actually keep on.**

```ts
betterSchemic(db, { schema, logger: true });   // or BETTER_SCHEMIC_LOG=1
```

│   WHERE role = $p0                               │
│ $p0 = "member"                                   │

## Get started

```bash
bun add better-schemic
bunx better-schemic init        # or `sc init`
```

One package. `init` writes the config, a sample schema, a seed stub and `.env.example` — no account,
no cloud, nothing to undo. Zod and the SurrealDB SDK ship inside `better-schemic`, so there is
nothing else to install (and no second copy of Zod to break `s.*`).

```ts
// better-schemic.config.ts
import { defineConfig } from "better-schemic/config";
import { surrealConnection } from "better-schemic/connection";

export default defineConfig({
  connections: {
    default: surrealConnection({
      schema: "./database/schema",
      url: process.env.SURREAL_URL ?? "ws://127.0.0.1:8000/rpc",
      namespace: process.env.SURREAL_NAMESPACE ?? "app",
      database: process.env.SURREAL_DATABASE ?? "app",
      username: process.env.SURREAL_USER,
      password: process.env.SURREAL_PASS,
      authLevel: "root",
    }),
  },
});
```

```bash
sc diff      # what's changed          sc check   # replay migrations in a throwaway engine
sc gen       # write a migration       sc migrate # apply pending
sc rollback  # revert                  sc pull    # introspect the live DB back into TypeScript
```

## One schema. Every layer it touches.

Generate the DDL, run the migrations, keep the types — all from the file you already wrote.

**No lock-in.** MIT. `sc pull` takes a live database back into TypeScript at any time, and `$raw`
covers anything the delegates don't. Leaving is a command, not a migration.
